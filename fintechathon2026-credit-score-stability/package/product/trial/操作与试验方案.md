# 参考尺度复核作业试验

本试验固定案例版本及历史评分读数，A／B／C三种界面使用相同数据。主工作台展示容量保护后的最新评分；试验结果用于比较界面与证据接续的效果。

这套工具比较三种界面能否帮助从业者更准确、更快地完成复核。案例全部来自公开真实月度账务；不包含未来结果。当前没有真人试验结果。

## 启动与操作

Python 3.10 及以上即可启动网页服务，不需要外部模型、API key 或联网。在此目录执行 `python server.py --port 8768`，浏览器打开 `http://127.0.0.1:8768`。Windows 可双击“启动试验.bat”。网页服务只监听本机，适合主持人组织的现场试验；远程多用户接入前还需机构身份系统与正式部署。

1. 主持人讲解复核任务和计时规则。参与者自愿登记匿名岗位与经验；先查看独立练习案件。
2. 每人完成 9 个案件，各界面 3 个。未点“开始”时不展示正式案件，避免先读后计时。
3. 界面 A 给出账务表；B 增加账务轨迹；C 增加参考尺度核对、使用率分解、带来源的接续草稿。三组底层记录、参考额度、质量读数、凭证缺失状态完全相同。
4. 正式任务按前台聚焦时间计量，另存服务器墙钟时间；离开页面暂停前台计时。每次提交写入新版本，重复请求不重复计数，刷新可恢复会话。
5. 材料交由独立复核者评分；复核者不看到界面条件或参与者身份。退回材料在原案件接续，累计包括返工在内的时间。

## 分配方案

18 个正式案件按三类可观察情形各取 6 个：余额上升而实际使用率下降、月内支付未覆盖最低应还的新差额、其余情形。取样只使用评分时已有账务，固定哈希顺序，不读取未来逾期。另有 3 个练习案件，不进入正式分配。

在“岗位 × 经验”层内，使用全部 6 种 A/B/C 顺序。每个完整 6 人区组使用相同 9 个案件，每个案件在每种界面出现两次；下一区组使用另外 9 个案件。同一参与者从不重复看到同一正式案件。每种界面均包含三种案件情形。较小层内的不完整区组保留并在结果中报告。

首轮计划招募 24 名具有相关经验的参与者，估计差异、方差与流程可用性。下一轮用先导试验的参与者配对方差和目标最小收益计算人数，事先冻结分析方案。按实际业务案件占比加权的推广试验需另行抽样。

## 指标与业务验收

主比较为 C 对 B，A 为次比较。必须同时报告：

- 客观准确率：余额差、实际使用率、参考使用率、支付关系、额度动作证据状态五项全部正确。
- 完整正确率：五项正确，材料字段完整，盲评的证据完整性与处理适当性均为 2 分，且最终通过。
- 每个完整正确案件的作业耗时：全部已投入的前台时间（含失败和返工）÷ 完整正确案件数。分母为零时留空。
- 已分配、已启动、已提交、已评分、已退回数量；拒绝参与及中止人数由主持人另行登记。

建议进入小规模业务试点的判断条件：C 对 B 的完整正确率差的 95% 下限不低于 -5 个百分点，且每个完整正确案件耗时差的 95% 上限低于 0。若样本不足或区间跨界，继续测量。5 个百分点须由业务负责人在真人试验开始前确认；它是试验设计阈值，并非已达到的性能。

脚本按参与者成组重采样，适用于这 18 个固定案件；同一人的三种界面记录共同重采样。若推广到更广案件分布，还需扩展案件库并做参与者与案件的交叉层级分析。当前脚本不会将程序测试记录并入从业者收益。

## 盲评与返工

安装 `numpy pandas` 后运行：

```bash
python measure.py export
```

将 `measurements/blind_review_packets.json` 与 `blind_grades.csv` 交给复核者，评分规则如下：

|维度|0 分|1 分|2 分|
|---|---|---|---|
|证据完整性|结论没有来源或引用错误|主要判断有来源，但缺前后期或参考尺度|关键判断可追溯到前后期与参考额度，明确缺失凭证|
|处理适当性|直接推断信用改善、到期违约或直接提降额|能指出变化，但接续事项不够明确|区分算术变化和风险判断，明确要核对的凭证与下一步|

`decision` 填 `approved` 或 `return`，`reviewer` 填匿名复核员编号；`note` 填接续意见。以读数、来源和处理意见作为统一评分依据，各界面采用相同标准。两名复核者可先独立评分；分歧经协商后导入最终评分，并另留独立评分用于一致性分析。

```bash
python measure.py grade --grades measurements/blind_grades.csv
python measure.py analyze
```

没有从业者记录时，分析只输出“等待试验”，不产生节时、正确率或收益结果。程序功能测试位于单独 `automation.sqlite`，标记 `automation`，即使分析该库也会自动排除。

## 业务接入与商业测量

这套试验对应“复核员—运营接续岗—策略负责人”的真实任务交接。后续接入以账户月度快照、额度审批凭证、参考周期、案件版本五个对象为基本合同；先做只读并行复核，保留原授信决策流程。

试点按以下顺序推进：

1. 模型策略岗确认动作类别与重新锚定条件；数据岗核对账单日、支付入账及审批生效日期。
2. 复核岗运行两周并行作业，测量本工具的准确性、完整性与全部投入时间。
3. 客户运营岗验收接续材料是否可直接使用，记录退回原因；策略负责人验收漂移告警与风险名单的变化。
4. 技术负责人补齐机构身份、权限、日志留存、业务系统接口与异常恢复后，再讨论受控接入。

若测得每个完整案件节约 `Δt` 分钟，每月完成 `N` 件，综合人力成本为 `c` 元/小时，则月度毛工时价值为 `N×Δt×c/60`。净价值再扣除集成、维护、模型监控、复核与培训成本。当前未填入任何假定节时收益，也不把早期逾期覆盖率直接折算成坏账损失下降。

## 作业视图与界面复核

账务核对提供六期原始记录；图表分析增加余额、实际额度、总支付和最低应还的趋势视图；参考尺度协同增加三尺度分解与带来源草稿。界面按“原始账务—趋势分析—证据协同”切换，办理材料固定在右侧。三种方式共用相同字段、任务表和评分规则。

运行 `python product/trial/run_verification.py` 可检查任务分配、重复提交、刷新恢复、返工接续和网页视图切换。网页检查依赖 `product/package.json` 中的jsdom。
